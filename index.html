ข้อกำหนดเฉพาะงาน Renovate (Advance Draft QC Booking), การประเมินและให้คะแนนงานย่อย BOQ 1-5 ดาว, และเงื่อนไขยิง API ส่งผลตรวจไป STK 100%

1. แดชบอร์ดสไตล์ Step 1
  • • 4 KPI Cards: ยอดเข้าทั้งหมด, เข้าวันนี้, ยอดคงเหลือ, สถานะ SLA (Default 24 ชม.)
  • • Segment Bar: แถบสรุปสัดส่วน Quick vs Renovate
  • • Latest on Top: งานเข้าใหม่ล่าสุดอยู่บนสุดเสมอ พร้อมป้าย NEW!
2. ความต่างเฉพาะงาน Renovate
  • • Auto-Draft QC: เมื่อเตรียมแผนงานใน Step 3 เข้า Gantt ระบบจะสร้าง Job รอตั้งเป็น Draft QC ทันที
  • • Advance Booking: จองคิวหัวหน้าช่าง QC และกดยืนยันนัดหมาย (Confirm Booking) ล่วงหน้า
  • • 24-Hour Clock: ระบบเวลา 24 ชม. (ไม่มี AM/PM) + Presets +3 วัน, +5 วัน
  • • Gantt Sync: คลิกป้าย QC บน Gantt จะกระโดดมาหน้าจองช่างทันที
3. ระบบคะแนน ผ่าน=5 / ไม่ผ่าน=1
  • • Sub-Tasks: ดึงรายการงานย่อยจาก BOQ (รื้อถอน, ปูกระเบื้อง, สุขภัณฑ์, ระบบไฟ)
  • • Binary Scoring: ประเมินผ่าน (Yes) = 5 คะแนน, ไม่ผ่าน (No) = 1 คะแนน (ไม่มีให้คะแนนตามดาว)
  • • PASS / DEFECT: สลับสถานะผ่านหรือมีข้อบกพร่องตามเกณฑ์คะแนน
  • • Sub-task Photos: ถ่ายและแนบรูปภาพเฉพาะแต่ละงาน พร้อม Lightbox ซูมดูภาพ
4. กฎเหล็กส่งข้อมูลไป STK 100%
  • • Strict Gating: ต้องตรวจและประเมินงานย่อยครบ 100% จึงจะปลดล็อกปุ่มอนุมัติ
  • • Progress Bar: แถบวัดความคืบหน้าแจ้งเตือนชัดเจนหากยังตรวจไม่ครบ
  • • Dispatch to STK: เมี่อกดอนุมัติ สถานะเปลี่ยนเป็น QC_PASSED และยิง REST API ส่งข้อมูลผลตรวจ (เลขที่, คำถาม, คะแนน) ไปยังระบบ STK ทันที

คำถามที่พบบ่อย (Frequently Asked Questions - FAQ)

รวมคำตอบและแนวทางแก้ไขปัญหาสำหรับการใช้งานระบบ PMT Flow

Q1: ทำไมรายการวัสดุ (Material Items) จึงไม่ถูกแปลงเป็น Task ในแผนงาน Gantt Timeline?
คำตอบ: ตามกฎเกณฑ์ทางธุรกิจของระบบ PMT (Labor-Only Rule) แผนงานติดตั้ง (Gantt Timeline) มีวัตถุประสงค์เพื่อกำหนดตารางเวลาและมอบหมายภาระงานให้ทีมช่าง ดังนั้นเฉพาะรายการที่เป็น "ค่าแรง หรือ งานบริการ" (เช่น งานติดตั้ง, งานรื้อถอน, งานเดินท่อ, งานทาสี) เท่านั้นที่จะถูกนำมาสร้างเป็น Task ดำเนินงาน ส่วนรายการ "วัสดุและอุปกรณ์" (เช่น ขาแขวน, ท่อทองแดง, เบรกเกอร์, สี) จะถูกจัดเก็บไว้ในตารางคำนวณราคาและ BOQ เพื่อใช้คิดเงินและตัดสต็อก แต่จะไม่ถูกนำไปรบกวนตารางเวลาการทำงานของช่าง
Q2: เงื่อนไขและกฎเกณฑ์ในการ Check-in หน้างานของทีมช่างมีอะไรบ้าง?
คำตอบ: การ Check-in ต้องผ่าน 2 เงื่อนไขสำคัญ:
  • ระยะพิกัด GPS: พิกัดของช่างต้องอยู่ภายในรัศมีไม่เกิน 400 เมตรจากพิกัดสถานที่ติดตั้งของลูกค้า (หากเกิน 400 เมตร ระบบจะแจ้งเตือนระยะห่างและไม่อนุญาตให้บันทึก)
  • รูปถ่ายหน้างาน: ต้องแนบภาพถ่ายหน้างานจริงอย่างน้อย 5 รูปขึ้นไป เพื่อเป็นหลักฐานยืนยันก่อนเริ่มงาน
Q3: การนำเข้าไฟล์ใบเสนอราคา Excel (.xlsx, .xls) ทำงานอย่างไร และใช้ราคาแบบใด?
คำตอบ: ระบบเชื่อมต่อเอนจิน SheetJS ในการถอดรหัสไฟล์ Binary Excel (.xlsx/.xls) โดยจะ **เปิดอ่านข้อมูลจาก Sheet หน้าแรกสุด (Sheet Index 0) เสมอเป็นค่าเริ่มต้น** พร้อมตัวเลือก Dropdown ให้ผู้ใช้สลับไปดู Sheet อื่นได้ และข้อมูลราคาต่อหน่วย (ค่าวัสดุและค่าแรง) ที่นำเข้าจะนำไปคำนวณราคารวม (Subtotal), หักส่วนลดโครงการ (Discount) และหายอดสุทธิ (Grand Total / No VAT) อัตโนมัติ 100%
Q4: หากต้องการถอยสถานะของ Job หรือล้างข้อมูลโครงการทั้งหมด ต้องทำอย่างไร?
คำตอบ:
  • ถอยสถานะทุกโครงการ: กดปุ่มสีส้ม "ถอยสถานะเป็น Survey" ที่แถบเครื่องมือของหน้าแผนงานหรือหน้ารายการงาน เพื่อรีเซ็ตสถานะของทุกโครงการกลับเป็น Survey (25% พร้อมรูปสำรวจหน้างาน เพื่อให้ PM/SA ทำแบบแปลนและประมาณการ BOQ)
  • ปรับสถานะรายโครงการ: ในหน้า Project Detail ด้านบนขวา จะมีเมนู Dropdown "ปรับสถานะ" ให้เลือกเปลี่ยนสถานะกลับไปมาระหว่าง Survey, In Progress, QC Pending, QC Passed ได้ตลอดเวลา
  • ล้างข้อมูลโครงการทั้งหมด: กดปุ่มสีแดง "ลบข้อมูลโครงการทั้งหมด" เพื่อรีเซ็ตฐานข้อมูลเป็นสถานะว่างเปล่า (0 โครงการ / 0 Tasks)
Q5: ระบบสัญญาบริการ MA (Maintenance Agreement) หลังการขายทำงานอย่างไร?
คำตอบ: เมื่อโครงการผ่านการตรวจรับงาน QC และส่งมอบงานแล้ว ระบบสามารถสร้างสัญญา MA ดูแลรักษาต่อเนื่อง (เช่น ล้างแอร์หรือตรวจเช็คระบบน้ำทุก 3 เดือน รวม 4 รอบต่อปี) โดยระบบจะคำนวณตารางรอบการเข้าบริการล่วงหน้า (Service Schedule Timeline), ติดตามสถานะแต่ละรอบ (Completed / Pending), และส่งแจ้งเตือนเมื่อใกล้ถึงรอบเข้าบริการของลูกค้า
Q6: ทำไมระบบจึงปรับใช้เฉพาะ "ธีมสว่าง (Light Theme)" และมีกลไกป้องกันหน้าจอ Login ค้างอย่างไร?

คำตอบ: เพื่อให้การอ่านข้อมูลหน้างาน ตาราง Gantt แผนผังแบบแปลน และข้อมูลตัวเลข BOQ มีความคมชัดสูงสุด ไม่กลืนกับพื้นหลัง ระบบ PMT Flow จึงกำหนดมาตรฐานเป็น ธีมสว่าง (Light Theme) 100% และยกเลิกการสลับโหมดมืด เพื่อตัดปัญหาความขัดแย้งของสีและคอนทราสต์อย่างถาวร

สำหรับระบบ Log-on / Log-out ได้รับการยกระดับด้วยกลไก In-Memory Fast Auth (0ms response), การตั้งเวลา Timeout ป้องกันการค้าง, และระบบ Hard Reload Redirect เมื่อออกจากระบบ เพื่อล้างหน่วยความจำและตัวจับเวลาในเบื้องหลังอย่างสมบูรณ์ ป้องกันปัญหาหน้าจอค้าง 100%

Q7: หลังจากบันทึกผลการประเมินความพึงพอใจลูกค้า (CSAT) แล้ว สามารถแก้ไขคะแนนได้หรือไม่?

คำตอบ: ไม่สามารถแก้ไขคะแนนได้ เพื่อรักษาความถูกต้อง โปร่งใส และป้องกันการแก้ไขผลการดำเนินงานย้อนหลัง (Audit Trail & Governance Integrity) โดยเมื่องานได้รับการประเมินแล้ว ปุ่มในตารางจะเปลี่ยนเป็น 👁️ ดูผลประเมิน และหน้าต่างผลประเมินจะปรับเป็น "โหมดดูข้อมูลเท่านั้น (Read-Only Mode)" ล็อกคะแนนดาว ข้อคิดเห็น และรูปภาพประกอบ แต่เจ้าหน้าที่สามารถคลิกเข้ามาตรวจสอบข้อมูลย้อนหลังได้ตลอดเวลา

Q8: 5 ข้อคำถามมาตรฐานการประเมินคุณภาพ QC (Isara Chootip Standard) และเกณฑ์การให้คะแนน Yes/No มีอะไรบ้าง?

คำตอบ: การตรวจรับรองคุณภาพ QC (Step 5) กำหนดให้ประเมิน 5 ข้อคำถามมาตรฐาน โดยใช้ระบบคำตอบ Yes / No (คะแนน Yes = 5 คะแนน, No = 1 คะแนน):

  1. ช่างทำงานตาม BOQ/มาตรฐานการติดตั้งที่กำหนด (หมวด: มาตรฐาน & BOQ)
  2. ความเรียบร้อยของงานติดตั้ง (หมวด: คุณภาพงานติดตั้ง)
  3. ช่างเข้าปฏิบัติงานตรงตามเวลาที่นัดหมายกับลูกค้า (หมวด: การตรงต่อเวลา)
  4. ส่งมอบงานได้ตามกำหนดเวลา (หมวด: กำหนดเวลาส่งมอบ)
  5. ช่างป้องกันพื้นที่ติดตั้งและส่งมอบพื้นที่คืนโดยไม่เกิดความเสียหาย (หมวด: การป้องกัน & คืนพื้นที่)

เกณฑ์คะแนนรอบแก้ไข (Rework Pass): หากข้อคำถามหรือใบงานเคยกดไม่ผ่าน 1 รอบแล้ว (กด No หรือกดแจ้งช่างแก้ไขงาน Rework) เมื่อช่างแก้ไขงานแล้วตรวจให้ผ่านในรอบถัดไป ข้อคำถามนั้นจะได้รับ 1 คะแนน (ผ่านรอบแก้ไข) แทน 5 คะแนน เพื่อสะท้อนประวัติการบกพร่องตามจริง

ผู้ตรวจสามารถกดปุ่มลัด "✓ เลือก Yes ทั้งหมด" เพื่อความรวดเร็ว และระบบมีกลไก Gating Rule บังคับต้องตรวจครบทุกข้อโดยไม่มีข้อบกพร่องคงค้าง จึงจะสามารถปลดล็อกปุ่มอนุมัติส่งต่องานไปยังขั้นตอน CSAT (Step 6) ได้

Q9: ทำไมโครงการ Renovate หากยังไม่ผ่านการจัดทำ BOQ ใน Step 1 ปุ่มส่งต่อไป Step 3 จึงถูกล็อกและกดไม่ได้?

คำตอบ: ตามโครงสร้างและสถาปัตยกรรมของระบบ PMT Flow หน้าจอ Step 3 (เตรียมแผนงานและทีมช่าง / Work Preparation) ทำหน้าที่แปลงรายการค่าแรงและบริการจากเอกสาร BOQ ให้กลายเป็น Work Tasks บนแผนงาน Gantt Chart (Labor-to-Task Rule)

ดังนั้น หากคำสั่งซื้อยังไม่มีข้อมูล BOQ (มี 0 รายการ) ระบบจะไม่สามารถสร้างแผนงานช่างบน Gantt ได้ ระบบจึงมีเกณฑ์ความปลอดภัย (Fail-Safe Gatekeeper) บังคับว่า:

  • ในหน้าต่าง All-in-One Studio หากยังไม่มีรายการ BOQ ปุ่มด้านล่างจะถูก Disable (ล็อกสถานะปิดใช้งาน) เปลี่ยนเป็นข้อความ 🔒 รอจัดทำ BOQ ใน Step 1 (ก่อนไป Step 3) และแสดงป้ายเตือน ❌ ยังไม่มี BOQ
  • เมื่อเจ้าหน้าที่กรอกรายการ BOQ ในแท็บ 3 หรือนำเข้าไฟล์ Excel/Template อย่างน้อย 1 รายการ ปุ่มจะ ปลดล็อกอัตโนมัติ (Reactive Unlock) เป็นสีม่วง 🚀 อนุมัติ & แปลงเข้า Gantt (Step 3) และแถบด้านบนจะเปลี่ยนเป็น ✓ ผ่านแล้ว ทันที
Q10: มาตรฐานการแสดงผลและเลือกวันที่ (Date Format Standard: DD/MM/YYYY) และระบบ Flatpickr ทำงานอย่างไร?

คำตอบ: เพื่อป้องกันความสับสนเรื่องวัน/เดือน (เช่น 10 กันยายน vs 9 ตุลาคม) ระบบ PMT Flow กำหนดมาตรฐาน วัน/เดือน/ปี ค.ศ. (`DD/MM/YYYY`) 100% สำหรับทุกหน้าจอและทุกโมดอล

โดยระบบใช้ Custom Light-Theme Flatpickr (`data-datepicker="true"`) แทน Native Date Picker ของเบราว์เซอร์อย่างถาวร เพื่อป้องกันไม่ให้ Windows/Chromium OS Locale สลับเป็น MM/DD/YYYY พร้อมมีกลไก Helper อัจฉริยะ (formatDateDMY, formatDateTimeDMY, formatDateISO) แปลงค่าส่งต่อ Backend API อย่างปลอดภัย 100%

Q11: สถาปัตยกรรม One-Stop Order Studio (Step 1) และการนำเข้าสถานะ Survey (25%) จาก API ทำงานอย่างไร?

คำตอบ: คำสั่งซื้อที่เชื่อมโยงผ่าน Inbound API จะเข้าสู่ระบบด้วยสถานะ "Survey" (`SURVEYED` / ความคืบหน้า 25%) โดยทันที เพื่อสะท้อนว่าผ่านการสำรวจพื้นที่หน้างานและถ่ายรูปเบื้องต้นแล้ว โดยมีจุดเด่นของสถาปัตยกรรมดังนี้:

  • Ultra-Wide Executive Workspace: หน้าต่าง Modal ขนาดใหญ่พิเศษ (w-[96vw] max-w-7xl h-[96vh]) ออกแบบเฉพาะสำหรับ Project Manager (PM) และ Solutions Architect (SA) เลื่อนดูข้อมูลแบบต่อเนื่อง (Continuous Vertical Scrolling) ครบ 3 ส่วนในหน้าเดียว
  • คลังรูปถ่ายสำรวจหน้างาน (Section 1): แสดงภาพถ่ายสำรวจหน้างานจริง พร้อมปุ่ม + 📷 เพิ่มรูปถ่ายหน้างาน ให้อัปโหลดภาพเพิ่มเติมได้ทันทีก่อนเริ่มงาน พร้อม Lightbox ซูมดูรูปใหญ่และปุ่มลบภาพ
  • แบบแปลนติดตั้ง CAD/PDF (Section 2): คลังจัดเก็บแบบแปลนแยกตามโซนห้อง พร้อม Drag & Drop Uploader และพรีวิวไฟล์แบบแปลน
  • ประมาณการราคา BOQ (Section 3): ตารางคิดราคาพร้อมปุ่ม Quick Service Preset Chips (+ค่าแรงติดตั้ง, +ท่อน้ำยา, +รางครอบท่อ ฯลฯ) ช่วยให้เพิ่มรายการได้ในคลิกเดียว พร้อมคำนวณราคาสุทธิ (Grand Total / No VAT) อัตโนมัติ
  • Live Metrics & Sticky Quick Jump: แถบ Header แสดงจำนวนรูปถ่าย แบบแปลน และยอดรวม BOQ สด และมีปุ่มทางลัดช่วยเลื่อนสกรอลล์ไปยังแต่ละส่วนได้อย่างรวดเร็ว
Q12: แผนงาน Gantt Chart แบบ Real-time รายวันแสดงสถานะสีอย่างไร และเงื่อนไขการอัปเดตย้อนหลัง 3 วันมีกฎเกณฑ์อย่างไร?

คำตอบ: แผนงาน Gantt Chart ของระบบ PMT Flow ได้รับการอัปเกรดเป็น Real-time Daily Timeline Engine ที่จำแนกและติดตามความคืบหน้ารายวันของช่างและทีม QC แบบวันต่อวัน โดยใช้รหัสสีมาตรฐานดังนี้:

  • 🟢 สีเขียว (✓ เสร็จสิ้น): วันที่ช่างหรือ QC ได้เข้ามาลงบันทึกความคืบหน้าเรียบร้อยแล้ว (จะขึ้นสีเขียวเฉพาะวันที่มีการอัปเดตงาน)
  • 🔴 สีแดง (ยังไม่อัปเดต): วันทำงานตั้งแต่เริ่มสัญญาจนถึง "วันนี้" (Today) ที่ยังไม่มีการส่งบันทึกงาน เพื่อแจ้งเตือนให้เจ้าหน้าที่และช่างเร่งดำเนินการ
  • 🟣 สีม่วง (Xd / ช่วงเวลาที่ยังไม่เริ่ม): วันทำงานในอนาคตที่ยังมาไม่ถึงตามกรอบระยะเวลาของ Task

กฎเกณฑ์การอัปเดตย้อนหลัง (3-Day Retroactive Policy):

  • สามารถคลิกที่แท่งสีแดงบน Gantt หรือคลิกเม็ดยาในโมดอล เพื่อ อัปเดตงานย้อนหลังได้ไม่เกิน 3 วัน นับจากวันปัจจุบัน
  • หากพ้นกำหนดเกิน 3 วัน ระบบจะทำการล็อกสถานะ (เกิน 3 วัน (ล็อค)) และไม่อนุญาตให้บันทึกย้อนหลัง เพื่อรักษาความถูกต้องของบันทึกเวลาปฏิบัติงานจริง
  • มีเส้นบอกตำแหน่ง "วันนี้" (Today Indicator) เส้นประสีแดงในแนวตั้งพร้อมจุดกำกับแถว เพื่อให้เห็นรอยต่อระหว่างอดีต ปัจจุบัน และอนาคตได้ทันที
Q13: การนำเข้าใบ BOQ / ใบเสนอราคา vFIX (Import BOQ) มีการทำงานอย่างไร มีเงื่อนไขการคัดกรองหัวข้องานอย่างไร และทำไมระบบจึงไม่เปลี่ยนชื่อลูกค้าเดิมของโครงการ?

คำตอบ: เพื่อให้การนำเข้า BOQ ได้เฉพาะรายการทำงานจริงและรักษาความถูกต้องของข้อมูลลูกค้าเดิม ระบบ PMT Flow มีเงื่อนไขและมาตรการสำคัญดังนี้:

  • นำเข้าเฉพาะหัวข้อที่ขึ้นต้นด้วย "'งาน" หรือ "งาน" เท่านั้น (Strict Work Header Filter): ระบบจะดึงเฉพาะรายการที่ชื่อรายการ/รายละเอียดสินค้าขึ้นต้นด้วย "'งาน" หรือ "งาน" เข้าสู่ตาราง BOQ เท่านั้น รายการวัสดุ/อุปกรณ์ย่อย (เช่น ชุดท่อน้ำยาแอร์, รางครอบ, ขาแขวน) หรือแถวสรุปยอด (รวมเงิน, ภาษีมูลค่าเพิ่ม) จะถูกข้ามออกไปโดยอัตโนมัติ เพื่อป้องกันข้อมูลขยะและให้ตารางสะท้อนหมวดงานจริง
  • นำเข้าเฉพาะรายการ ไม่ใส่เงินและจำนวน: ระบบจะนำเข้าเฉพาะรหัสและชื่อรายการงาน โดยไม่ใส่ยอดเงิน (ค่าวัสดุ = 0, ค่าแรง = 0, รวมเงิน = 0) และไม่ใส่จำนวน (แสดงเป็น - หรือ 0) เพื่อความคล่องตัวในการเตรียมแปลงเป็นรายการ Task ใน Gantt Timeline โดยตรง
  • ล็อคข้อมูลลูกค้าเดิม 100% (Customer Name Protection Standard): ข้อมูลชื่อลูกค้า, เบอร์โทรศัพท์, ที่อยู่หน้างาน, สาขา และวันที่ของโครงการเดิม จะไม่ถูกจับคู่หรือเขียนทับโดยเด็ดขาด ไม่ว่าหัวเอกสารในไฟล์ Excel หรือ AI OCR จะระบุชื่อลูกค้าท่านใดก็ตาม
  • ข้อมูลหัวเอกสารเพื่อการอ้างอิงเท่านั้น: หากตรวจพบข้อมูลหัวเอกสารในไฟล์ vFIX ระบบจะจัดเก็บเป็น Metadata อ้างอิงแหล่งที่มาของเอกสารต้นทาง เพื่อใช้ในการตรวจสอบย้อนกลับ (Audit Trail) เท่านั้น โดยไม่กระทบข้อมูลหลักของโครงการ
Q14: หน้าจอ "รายงานที่สำเร็จแล้ว (Job Close)" และระบบสืบค้นประวัติย้อนหลัง 6 เดือน (Order History Tracking & Work Photos) ทำงานอย่างไร?

คำตอบ: หน้าจอ "รายงานที่สำเร็จแล้ว (Job Close)" รวบรวมประวัติโครงการที่ส่งมอบสำเร็จและปิดงานแล้ว เก็บประวัติย้อนหลังได้ 6 เดือนเต็ม เพื่อให้ผู้บริหารและทีมงานสแกนผลการดำเนินงาน สืบค้นประวัติ และเรียกดูหลักฐานหน้างานได้อย่างครบถ้วน 100%:

  • การเก็บข้อมูลประวัติย้อนหลัง 6 เดือน: มีตัวกรองช่วงเวลาให้เลือกดู 30 วัน, 60 วัน, 90 วัน, 180 วัน (6 เดือน) หรือดูทั้งหมด
  • แกลเลอรี่ภาพงานจริง 5 ขั้นตอน (Work Photos Gallery): โมดอลสรุปผลแสดงภาพถ่ายจริงก่อน-หลังปฏิบัติงาน, แนวท่อ/สายไฟ, ระบบไฟฟ้า/สายดิน และแบบแปลน พร้อม Lightbox ขยายดูภาพระดับ HD
  • ประวัติและไทม์ไลน์งาน 6 สเต็ป (Order History & Milestones): บันทึกประวัติและวันเวลาทุก Milestone (Intake ➔ BOQ ➔ Ticket ➔ Work Prep ➔ Daily Log ➔ QC ➔ CSAT ➔ BMT Sync) พร้อมระบุชื่อผู้ปฏิบัติงาน
  • การส่งออกไฟล์ Excel (.xlsx): รองรับการ Export รายงานฉบับสมบูรณ์เป็นไฟล์ Excel (.xlsx) แยก 2 Sheets (ตารางสรุปโครงการ และสรุปดัชนีชี้วัด KPI สถิติคะแนน)
  • สูตรคำนวณคะแนนรวม: (คะแนน QC + คะแนน CSAT) ÷ 2 (ปัดเศษทศนิยม 1 ตำแหน่ง)
Q15: หน้าจอ Standalone Inbound API Monitor (/apimonitor) และการตรวจสอบ Traffic API แบบแยกหน้าต่างทำงานอย่างไร?

คำตอบ: ระบบ PMT Flow มีหน้าจอเฉพาะทาง Standalone Inbound API Monitor ที่ URL https://vibepmt.online/apimonitor (หรือคลิกปุ่ม "เปิดหน้าต่างแยก" บนหัวตาราง Inbound API Logs และแถบเมนูด้านข้าง) เพื่อให้เจ้าหน้าที่และทีม Integrator มอนิเตอร์คำขอขาเข้าได้บนหน้าต่างอิสระหรือจอที่สองอย่างสะดวก

  • Auto-Detect Authentication: ตรวจจับ Token การเข้าสู่ระบบจาก PMT Flow อัตโนมัติ หากล็อกอินอยู่แล้วสามารถดูข้อมูลได้ทันที และมี Quick Sign-in Modal รองรับหากเปิดบนเครื่องอื่นหรือโหมด Incognito
  • Live Traffic & Configurable Auto-Refresh: อัปเดตข้อมูลสดทุก 3 วินาที (สามารถเลือก 2s, 3s, 5s, 10s หรือหยุดชั่วคราวได้) พร้อมไฟแสดงสถานะ Live Pulse สีเขียว
  • Audio Alert: สามารถเปิดเสียงแจ้งเตือนอัตโนมัติเมื่อมีคำขอผิดพลาดฝั่งไคลเอนต์ (4xx) หรือฝั่งเซิร์ฟเวอร์ (5xx) เกิดขึ้น
  • Inspect Payload, Response & Copy cURL: คลิกปุ่ม "ดูข้อมูล" เพื่อตรวจสอบ Headers, Request Payload, และ Response JSON แบบจัดรูปแบบสวยงาม พร้อมปุ่มคัดลอก cURL ไปรันต่อใน Postman หรือ Terminal ได้ทันที
Q16: การแสดงผลวันเวลาที่เข้าสู่ขั้นตอน / State (State Entry Timestamp) และการนับเวลา SLA ในคิวงานทำงานอย่างไร?

คำตอบ: เพื่อให้เจ้าหน้าที่ (SA / Admin / AE / Dispatcher) สามารถตรวจสอบได้อย่างแม่นยำว่าแต่ละโครงการเข้าสู่คิวงานในแต่ละขั้นตอนตั้งแต่เมื่อไหร่ และเริ่มนับเวลา SLA ถอยหลังตั้งแต่จุดใด ระบบ PMT Flow จึงแสดง "วันเวลาที่เข้า State นี้" (State Entry Timestamp) ควบคู่กับป้ายสถานะ SLA เสมอ:

  • คอลัมน์ "สถานะ SLA / เข้า State": ในตารางคิวงานทุกสเต็ป (Design/BOQ, Tickets & Receipts, Work Preparation/Conversion) ใต้ป้าย SLA จะแสดงบรรทัด เข้า State: DD/MM/YYYY HH:mm น. อย่างชัดเจน
  • การคำนวณและนับถอยหลัง SLA: ป้ายสถานะ SLA (เช่น ในเกณฑ์ (เหลือ 11 ชม. 59 น.) หรือ เกิน SLA +X ชม.) จะนำเวลาที่เข้าสู่ State นั้นจริง (step_timestamps) มาเปรียบเทียบกับเวลาปัจจุบันแบบ Realtime
  • รูปแบบเวลามาตรฐาน: แสดงผลในรูปแบบสากล DD/MM/YYYY HH:mm น. และใช้ระบบเวลา 24 ชั่วโมง (00:00 - 23:59 น.) ไม่มี AM/PM ตามข้อกำหนดมาตรฐานของระบบ 100%
Q16: กระบวนการ Fast-track สำหรับงานบริการด่วน (Quick Services) ทำงานอย่างไร มีขั้นตอนใดบ้าง และเหตุใดจึงปิด Step 2-3 และไม่ต้องไป Ticket?

คำตอบ: งานบริการด่วน (Quick Services เช่น ติดตั้งเครื่องปรับอากาศ, เครื่องทำน้ำอุ่น, ปั๊มแท็งก์น้ำ, โซลาร์เซลล์, กล้องวงจรปิด) เป็นงานที่มีแบบและราคามาตรฐานชัดเจน ระบบจึงออกแบบให้ทำงานแบบ Fast-track 1-Click to QC โดยสมบูรณ์:

  • ปิด Step 2 (Design) & Step 3 (BOQ) อัตโนมัติ: เมื่อเปิดหน้าต่าง One-Stop Studio สำหรับงาน Quick ระบบจะ Disable แท็บแบบแปลนและ BOQ พร้อมซ่อนเนื้อหาส่วนที่ 2 และ 3 เพื่อให้เจ้าหน้าที่ไม่ต้องเสียเวลากรอกข้อมูลที่ไม่จำเป็น
  • STAMP ข้อมูลช่าง มาจาก INT โดยอัตโนมัติ: ระบบจะดึงข้อมูลทีมช่างและช่างสำรวจที่ส่งมาจากระบบภายนอก (INT) มาใส่ในช่องช่างสำรวจ/ผู้รับผิดชอบทันที พร้อมติดป้ายกำกับ STAMP ข้อมูลช่าง มาจาก INT
  • วิ่งตรงสู่หน้าตรวจรับรอง QC ทันที (Bypass Ticket): เมื่อกดปุ่ม "บันทึกข้อมูล (Save)" หรือ "🚀 บันทึก & วิ่งไปหน้า QC ทันที" ระบบจะบันทึกข้อมูลและนำทางไปยังหน้าจอ ตรวจรับรองคุณภาพ QC (Step 5) พร้อมเปิดแบบฟอร์ม QC Online ให้ตรวจสอบภาพถ่ายและปิดงานได้ทันที โดยไม่ต้องผ่านหน้า Ticket หรือแปลงเข้า Gantt อีกต่อไป
Q17: เมนูใหม่ "ราคาโครงการ" (Project Pricing) และระบบบันทึกราคางานที่ปิดแล้ว มีหลักการทำงานอย่างไร เหตุใดจึงแยกราคาทุน vs ราคาขาย และไม่คิด VAT 7%?

คำตอบ: หน้าจอ "ราคาโครงการ" (`nav-project-pricing`) ออกแบบมาเพื่อคัดกรองเฉพาะงานที่ปิดงาน/จบงานแล้ว (Closed / Completed Jobs) เพื่อให้เจ้าหน้าที่ฝ่ายราคา ฝ่ายขาย และบริหาร ตรวจสอบและบันทึกราคางานโครงการได้อย่างแม่นยำ:

  • แยกคอลัมน์ "ทุน" และ "ราคาขาย" ชัดเจน: ตารางราคาในหน้าต่างบันทึกราคาโครงการจะแบ่งคอลัมน์สีฟ้า ทุน (฿) และสีม่วง ราคาขาย (฿) ไว้อย่างชัดเจน
  • สูตรการคำนวณแถวรายการ: ยอดรวมต่อแถวคำนวณจาก จำนวน x ราคาขาย เสมอ
  • บรรทัดหลังซัมเฉพาะราคาขาย (No VAT 7%): ยอดรวมทั้งสิ้น (Grand Total) จะรวมเฉพาะยอดราคาขายของหมวดค่าแรงและหมวดค่าวัสดุหลังหักส่วนลด โดย ไม่ต้องใส่หรือคิด VAT 7% ตามมาตรฐานงานโครงการ
  • ราคาทุนมีไว้สำหรับดูเป็นข้อมูลอ้างอิง: แสดงกล่อง "ราคาทุนรวม (Total Cost)" สีฟ้าเพื่อเปรียบเทียบต้นทุนจริงหน้างาน โดยไม่นำราคาทุนไปบวกเพิ่มหรือคิดภาษีปนกับราคาขาย
  • เครื่องมือช่วยการทำงาน: รองรับการกดปุ่ม ดึงข้อมูลจาก BOQ เพื่อคัดลอกรายการเดิมมาลงราคาได้ทันที และส่งออกเป็น Excel / CSV ได้ในคลิกเดียว
Q18: การเปิดให้ Key ชื่อช่างอิสระ และปุ่ม "จองช่างจาก INT" (ทำไว้รอเชื่อมต่อ API) ในหน้าจอแปลง BOQ มีการทำงานอย่างไร?

คำตอบ: ในหน้าต่าง "นำเข้า BOQ สู่ Project Tasks & แผนงาน Gantt" (`modal-convert-boq-tasks`) คอลัมน์ "ผู้รับผิดชอบ (ช่าง/Crew)" ได้รับการพัฒนาให้รองรับการทำงาน 2 รูปแบบอย่างยืดหยุ่น:

  • เปิดให้ Key ชื่อช่างได้โดยตรง (Free Text Keying): เจ้าหน้าที่สามารถพิมพ์ชื่อช่าง ทีมช่าง หรือเบอร์ติดต่อลงในช่อง Input ได้อย่างอิสระ พร้อมระบบ Autocomplete ดึงชื่อช่างที่คุ้นเคยมาช่วยแนะนำ
  • ปุ่ม "จองช่างจาก INT" (INT Booking Integration): แต่ละแถวมีปุ่ม จองช่างจาก INT เมื่อคลิกจะเปิดหน้าต่างดึงรายชื่อช่างจากระบบ INT พร้อมคะแนนดาวรีวิว (เช่น สมชาย ใจดี ★ 4.9, อนุรักษ์ มีสุข ★ 4.8, กมลวรรณ ★ 4.7) และปุ่มยืนยันการจองช่าง (Confirm) เพื่อออกเลขรหัสการจอง INT-BOOK-XXXX
  • ปุ่ม "จองช่างจาก INT ทั้งหมด": แถบเครื่องมือด้านบนมีปุ่มลัดสำหรับดึงและจัดสรรคิวช่าง INT ให้ทุกงานพร้อมกันในคลิกเดียว
  • ทำระบบรอเชื่อมต่อ API จริง: เมื่อกดจองช่าง ระบบจะจำลอง Request และบันทึกลงใน API Logs เพื่อให้ทีมพัฒนาระบบ INT สามารถเชื่อมต่อ Endpoint จริงได้ทันทีโดยไม่ต้องแก้โค้ดหน้าบ้านใหม่
Q19: การเพิ่มงานย่อย (Subtasks Breakdown) ในตารางแถบงาน Gantt Chart มีวิธีการใช้งานอย่างไร และเชื่อมโยงกับบันทึกงานช่างประจำวันอย่างไร?

คำตอบ: ในแผนงาน Gantt Timeline ทุกมุมมอง (รายวัน Day, รายสัปดาห์ Week, รายเดือน Month) และตารางรายการ Task ผู้ใช้สามารถจัดการงานย่อย (Subtasks) ของแต่ละ Task ได้อย่างสมบูรณ์แบบ:

  • ปุ่ม "+ Subtask" และปุ่ม "จัดการ" บนตารางแถบงาน: ในแต่ละแถวของ Task จะมีปุ่ม + Subtask เพื่อเพิ่มงานย่อยใหม่ได้ทันที และปุ่ม จัดการ เพื่อเปิดหน้าต่าง จัดการงานย่อย (Subtasks Breakdown Modal)
  • การแบ่งงานย่อยอัตโนมัติ (Auto-Split): มีปุ่ม ⚡ แบ่งย่อยอัตโนมัติ ที่จะคำนวณระยะเวลาของ Task และสร้างเฟสงานย่อยตามประเภทงาน (เช่น งานเตรียมฐานราก, โครงสร้างหลัก, ติดตั้งอุปกรณ์, ทดสอบระบบและส่งมอบ) อย่างต่อเนื่องไม่ซ้อนทับกัน
  • แถบแสดงผล Subtasks บน Timeline: ใต้แถว Task หลัก จะมีแถว Subtask พร้อมสัญลักษณ์ └─ และแถบสีความคืบหน้า (DONE สีเขียว, IN_PROGRESS สีส้ม, TODO สีม่วง) พร้อมจำนวนวันทำงาน (Xd)
  • เชื่อมโยงกับ Daily Work Log: คลิกที่แถบสีของ Subtask หรือคลิกไอคอนสมุดโน้ต บันทึกช่าง เพื่อเปิดแบบฟอร์มลงบันทึกงานประจำวันสำหรับงานย่อยนั้นๆ พร้อมระบุชื่อ Subtask ในหัวเรื่อง และอัปโหลดรูปถ่าย 5 รูปหน้างานได้อย่างไร้รอยต่อ
  • การซิงค์ข้อมูลแบบ Real-time: เมื่อปรับสถานะหรือความคืบหน้าของ Subtask ระบบจะคำนวณค่าเฉลี่ย % ความคืบหน้าของ Task หลัก และซิงค์บันทึกลงสู่ฐานข้อมูล Backend REST API ทันที
Q20: การกดเสร็จสิ้นงานช่างประจำวัน (100% / ส่งตรวจ QC) มีข้อกำหนด "User ยืนยัน" อย่างไร และหากลบบันทึก ระบบจะถอยสถานะให้อัตโนมัติหรือไม่?

คำตอบ: เพื่อป้องกันความเข้าใจผิดเมื่อช่างปฏิบัติงานเสร็จเร็วกว่าแผน (เช่น แผน 4 วัน แต่จบวันที่ 2 หรือจบวันสุดท้าย) ระบบ PMT Flow ได้บังคับใช้มาตรฐาน "User ยืนยัน" (Customer/User Sign-off Standard) ดังนี้:

  • ต้องผ่านการยืนยันจาก User: เมื่อกดปุ่มสีเขียว 🚀 ยืนยันสำเร็จ & ส่งตรวจ QC หรือติ๊กเลือก ช่างบันทึกสำเร็จ (User ยืนยัน) ระบบจะขึ้นกล่องถามยืนยันชัดเจนว่า User ได้ตรวจสอบและยืนยันงานเสร็จสมบูรณ์แล้ว
  • ระบุคำว่า "(User ยืนยัน)" อัตโนมัติ: รายละเอียดงานจะระบุข้อความ (User ยืนยัน) เสมอ และป้ายสถานะประวัติงานจะแสดง ✓ ช่างบันทึกสำเร็จ (User ยืนยัน) เพื่อเป็นหลักฐานตรวจสอบย้อนหลัง
  • ระบบคืนสถานะอัตโนมัติ (Auto Rollback): หากเผลอกดจบงานผิดวัน แล้วกดปุ่มลบ (ถังขยะ) บันทึกนั้นออก ระบบจะคำนวณถอยสถานะ Task และ Job กลับเป็น IN_PROGRESS ตามจำนวนวันที่บันทึกจริงทันที ไม่เกิดปัญหางานค้าง 100%
Q21: การจัดเรียงคอลัมน์มาตรฐาน 4 ข้อมูลแรก (เลขที่งาน, Ref ID, Booking No, กำหนดวันนัด) ในทุกคิวงาน (Step 1 - Step 6) มีมาตรฐานอย่างไร?

คำตอบ: เพื่อให้เจ้าหน้าที่ (SA / Admin / AE / QC) สามารถสแกนและตรวจสอบข้อมูลสำคัญของคำสั่งซื้อได้อย่างรวดเร็วในบรรทัดเดียว ระบบ PMT Flow จึงจัดเรียง 4 คอลัมน์แรกในตารางคิวงานทุกขั้นตอน (Step 1 ถึง Step 6) เรียงลำดับต่อเนื่องกันเสมอ:

  • 1. เลขที่งาน (Job ID): รหัสงานหลักในระบบ PMT Flow (job_no || id) พร้อมป้ายสถานะ NEW! สำหรับงานใหม่ล่าสุด
  • 2. เลขที่อ้างอิง (Ref ID): เลขที่เอกสารอ้างอิงภายนอกจากระบบ INT หรือระบบต้นทาง (external_ref_id) แสดงเป็น Badge สีฟ้า ชัดเจน
  • 3. เลขที่ Booking: รหัสการจองคิวงานจากระบบ Booking กลาง (booking_no) แสดงเป็น Badge สีม่วง
  • 4. กำหนดวันนัด: วันนัดหมายปฏิบัติงาน (plan_date) แสดงผลพร้อมไอคอนปฏิทินตามมาตรฐานวันที่ DD/MM/YYYY 100% (เช่น 18/09/2026)
  • การค้นหาแบบครอบคลุม: ช่องค้นหาหลัก (Global Search) และตัวกรองคิวงาน รองรับการพิมพ์ค้นหาทั้งด้วยเลขที่งาน, Ref ID, Booking No, วันที่นัดหมาย, ชื่อลูกค้า และเบอร์โทรศัพท์ ได้แบบเรียลไทม์
Q22: ข้อมูลที่ STAMP มาจากระบบ INT ทำไมจึงถูกล็อก (Read-Only) ใน PMT และประเภทบริการย่อย (project_sub_type) แสดงผลอย่างไร หากยังไม่มีจาก INT สามารถกรอก Manual ได้หรือไม่?

คำตอบ: เพื่อรักษาความถูกต้องของข้อมูลแหล่งกำเนิด (Single Source of Truth) และป้องกันปัญหาข้อมูลไม่ตรงกันระหว่างระบบต้นทาง INT กับ PMT Flow ระบบจึงมีนโยบายและการทำงานดังนี้:

  • ข้อมูล Stamp มาจาก INT ให้ PMT แก้ไม่ได้เลย (Strict Read-Only Guard): ข้อมูลสำคัญที่ผูกกับคำสั่งซื้อและใบจองจาก INT เช่น รหัสอ้างอิง (Ref ID), เลขที่ Booking, ชื่อลูกค้า, เบอร์โทรศัพท์, ที่อยู่หน้างาน, พิกัด GPS, ขอบเขตงาน, กำหนดวันนัดหมาย และช่างสำรวจ/ผู้รับผิดชอบ จะมีป้ายกำกับ STAMP ข้อมูลมาจาก INT และถูกล็อกสถานะอ่านอย่างเดียว (Read-Only / Disabled) ห้ามแก้ไขในระบบ PMT Flow เด็ดขาด
  • การแสดงผลประเภทบริการย่อย (project_sub_type): ระบบจะดึงข้อมูลบริการเฉพาะทางจากคอลัมน์ project_sub_type ในฐานข้อมูล (เช่น "บริการ Q-ติดตั้ง แอร์ติดผนัง ขนาด 17001 - 25000 บีทียู" หรือ "งานสำรวจ ติดตั้งประตู / หน้าต่าง 1 งาน") มาแสดงอย่างชัดเจนทั้งใน หัวข้อโมดอล (Header Subtitle) พร้อมป้ายสาขา/รหัสร้าน (store_code - agent_name), ช่องประเภทบริการใน Studio และในตารางคิวงานทุกสเต็ป
  • ข้อยกเว้นกรอก Manual ได้เฉพาะประเภทบริการ (Manual Fallback Policy): หากคำสั่งซื้อนั้นยังไม่ได้รับข้อมูลประเภทบริการย่อยมาจาก INT (หรือส่งมาเป็นค่าว่าง) ช่องประเภทบริการจะเปิดให้เจ้าหน้าที่ (PM / SA / AE) พิมพ์ระบุรายละเอียดบริการหรือเลือกจาก Datalist ได้เองทันที โดยระบบจะแสดงป้ายเตือนสีส้ม กรอก Manual (ยังไม่ได้รับจาก INT) พร้อมคำแนะนำ และเมื่อบันทึกข้อมูล ค่านี้จะถูกซิงค์บันทึกลงฟิลด์ project_sub_type และ service ในฐานข้อมูลทันที
